# Database Conventions

1. **Naming**: tables plural snake_case (`@@map`), columns snake_case (`@map`), Prisma models PascalCase singular.
2. **Primary keys**: `uuid` generated by PostgreSQL (`gen_random_uuid()`); join tables use composite keys.
3. **Organization scope**: every business table has `organization_id uuid NOT NULL` (global catalogues such as
   `permissions` and `hsn_sac_codes` are the documented exceptions). Every query filters by organization.
4. **Money and quantities**: money `Decimal(18,2)`; rates/percentages `Decimal(7,4)`; quantities `Decimal(18,4)`.
   Never `Float`/`Double`. See ADR-0004.
5. **Time**: `timestamptz(6)` for instants; `date` for business dates (financial years, effective dates).
   Business dates are interpreted in the organization's time zone (Asia/Kolkata by default); the transaction
   date and posting date of financial records are stored separately (Phase 2).
6. **Concurrency**: mutable tables carry `version int default 1`; updates use `WHERE id = ? AND version = ?`
   and increment it. Conflicts surface as `DB_0002` with a user-readable message.
7. **Deletion**: configuration rows are deactivated (`is_active`), never deleted once referenced. Posted
   financial/stock records are never deleted; corrections are reversal documents. FKs default to `RESTRICT`.
8. **Constraints in the database**: uniqueness, checks and immutability rules (audit log triggers) live in SQL,
   not only in application code. Rules Prisma cannot express are appended to the migration as marked SQL.
9. **Migrations**: forward-only, one directory per change under `prisma/migrations/`, applied with
   `prisma migrate deploy`; each change needs an automated migration test and a recovery note (spec section 37).
10. **Secrets**: no plaintext secrets in any column; credentials will be encrypted with an OS-protected key
    (Phase 3/5). Audit `before/after` values are redacted by the application before insertion.
11. **Indexes**: add an index only with a stated query; composite indexes begin with `organization_id`.
12. **Seeds**: `prisma/seed/reference` (safe for production) and `prisma/seed/demo` (fictional, marked DEMO
    DATA, never automatic).
13. **Encoding**: every cluster and database must be UTF8 (`initdb --encoding=UTF8`). The Windows default
    (WIN1252) cannot store Indian-language text; this was found in Phase 1 Task 1.0 (risk R-035) and is enforced
    for dev/test clusters and covered by an integration test. Production initialisation: requirement P6-ENC-01.
